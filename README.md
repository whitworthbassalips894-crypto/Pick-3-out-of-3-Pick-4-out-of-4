# 六合彩 · 选号助手（特码 / 三中三 / 四中四）

纯前端单页工具（PWA）。三种玩法各用**最贴合自己形态**的呈现方式：

| 玩法 | 每期形态 | 每期注数 |
| --- | --- | --- |
| **特码**（1 中 1） | **一张 12 号清单**（含 3 个 🎲 纯随机对照） | **12 注** |
| **三中三** | **5 组，每组 3 个号** | **5 注** |
| 四中四 | 5 组，每组 4 个号 | 5 注 |

> 特码是 **1 中 1**：1 个号 = 1 注，所以「号码个数 = 注数」。特码没有「组」的概念，
> 分组是「一组 = 一注组合」的形态（三中三 / 四中四才有），硬套到特码只会让人误以为每组是个整体。
>
> 三中三 / 四中四都是「一组 = 一注组合」：三中三每组 3 个号、四中四每组 4 个号，**每组 1 注**。

> 先把话说清楚：**每期开奖相互独立，没有任何选号方法能提高命中概率。**
> 本工具能做的只有两件事：① 如实算出概率与期望回报；② 让号码铺得开、把「至少中 1 注」的概率按真实号码算准。
> 彩票是娱乐，请量力而行。

## 三种玩法的概率（工具里也是这几组数）

| 玩法 | 每注号码 | 每期注数 | 单注命中概率 | 理论公平赔率 | 默认赔率 → 期望回报率 |
| --- | --- | --- | --- | --- | --- |
| 特码（1 中 1） | **1 个号** | **12 注**（12 号清单） | 1/49 ≈ **2.0408%** | 49 倍 | 48 倍 → **97.96%** |
| 三中三 | 3 个号 | 5 注 | C(6,3)/C(49,3) ≈ **0.1086%**（5 注至少中 1 注 ≈ **0.543%**） | ≈ 921 倍 | 650 倍 → **70.6%** |
| 四中四 | 4 个号 | 5 注 | C(6,4)/C(49,4) ≈ **0.00708%** | ≈ 14125 倍 | 7500 倍 → **53.0%** |

> 三种玩法都是「1 注 1 份本金」，默认 10 元/注：特码 12 注 120 元/期、三中三 5 注 50 元/期、四中四 5 注 50 元/期。

特码另外两组常用数字：
- 整张清单 12 个号至少中 1 注 = 12/49 ≈ **24.489%**
- 中了净赚 48 − 12 = **36 注**（收益率 **300%**）

**特码为什么是 12 注（不是 3 / 15 / 24）**

期望值 = −n/49 注（n = 注数），**永远是负的，且与 n 成正比** —— 买越多亏越多，
所以不存在「最优注数」，只有「更符合你想要的体验」的注数：

| 每期号数 n | 中奖概率 | 中奖净赚 | 收益率 |
| --- | --- | --- | --- |
| 6 | 12.2% | +42 注 | 700% |
| 9 | 18.4% | +39 注 | 433% |
| **12** | **24.5%** | **+36 注** | **300%** |
| 15 | 30.6% | +33 注 | 220% |
| 24 | 49.0% | +24 注 | 100% |
| 48 | 98.0% | 0 注 | 0% |

12 注落在「约 4 期中 1 次、中了赚 3 倍」的甜点区；15 / 24 注只是「更常中、但赚得更少」，
且每期多掏 25% / 100% 的本金。

命中口径：
- **特码**：**1 中 1**——1 个号就是 1 注，开奖的最后一个号码（特码）等于清单里哪个号，那一注就中（返 1 份奖金）。
  6 个正码不参与判定。
- **三中三 / 四中四**：整组的 3 / 4 个号**全部**落在 6 个正码里才算中，特码不计入。

赔率与本金可以在页面「本金与赔率」里改，回放金额会同步重算。

## 号码怎么出

### 特码：一张 12 号清单

| 风格 | 个数 | 选号逻辑 |
| --- | --- | --- |
| 🎲 完全随机 | 3 | **纯 49 选 3 等概率机选**，不排除任何号码（按期号定种，可重摇，作对照组） |
| 🔥 热号 | 3 | 近 30 / 60 期作为**特码**出现最活跃（按特码历史统计，不看正码） |
| 🎯 冷号 | 2 | 作为特码遗漏最久（按该号自身间距分位） |
| ⚖️ 形态均衡 | 4 | 补齐整体形态：奇偶 6:6 / 大小 6:6 / 三区 4:4:4 / 同尾最多 2 个 |

**为什么随机号先选**：🎲 的 3 个号先随机定下，剩下 9 个精选**避开它们**，
所以 12 个号天然互不重复 —— 一注都不浪费，整体「至少中 1 注」就是 12/49（精确值）。

**均衡是整体的，不是每组的**：旧版把「形态均衡」实现成「越靠近中值 25 分越高」，
配合每组 3 个号的三区配额，结果每期几乎都是 `16 25 35`（实测 300 期里占 24%）。
现在改成先按「理想分区模型」定下 4 / 4 / 4 的三区结构，再在每区里按分数取号，
最后用同区同奇偶的单号交换把奇偶、大小、三区、尾数补齐 —— 200 期实测 **200 种不同清单**。

### 三中三 / 四中四：5 组

| 组 | 名称 | 选号逻辑 |
| --- | --- | --- |
| #1 | 🎲 完全随机 | 纯 49 选 size 等概率机选，不排除任何号码、**允许与精选重复**（作对照组） |
| #2 | 🔥 热号 | 近 30 期出现次数最多 + EMA 活跃度，再加与已选号的形态搭配 |
| #3 | 🎯 冷号 | 按该号自身间距分布的遗漏分位，取遗漏最久的号 |
| #4 | ⚖️ 形态均衡 | 和值靠近理论均值，奇偶 / 大小 / 三区均衡（3 码注自然收敛成 1-1-1） |
| #5 | 🧩 补位覆盖 | 补齐 #2~#4 没覆盖到的尾数与区段，让精选四注铺得更开 |

**重叠规则**：#1 是纯随机，允许与精选撞号；#2~#5 四组精选之间互不重复。
号码内容不影响单注概率，但**重不重叠会影响「至少中 1 注」**，页面按当期真实号码精确计算：
两种直选都用**容斥公式精确算**（不是简单相加）：
三中三 ≈ **0.5427%**（5 × 单注 = 0.5428% 只是上界），四中四 ≈ **0.0354%**。

风格（热 / 冷 / 形态 / 补位）只决定「看起来怎么选」，不改变任何一注的命中概率。

## 页面

一页流，只保留必要区块：

1. **数据同步（置顶）** —— 进页面第一屏就是「一键同步」：读仓库 `data/draws.json` 补最新开奖，附「仅检查 / 以数据源为准修复冲突 / 粘贴导入 / 导入导出本机开奖 / 底库体检」。打开页面会自动跑一次「仅检查」。
2. **今日号码** —— 玩法切换（特码 / 三中三 / 四中四）、期数切换、号码卡片（特码 12 号清单 / 三中三 5 组 3 号 / 四中四 5 组 4 号）、一键复制、重摇随机号；
   顶部的「对齐凭证」显示 `期号 · 🎲#重摇次数 · 本机底库`，点一下复制当前网址，
   **手机和电脑打开同一个网址看到的就是同一张号码**（`?p=期号&salt=重摇次数&m=玩法`）。
   底部一行显示注数与总成本 / 单注与整张命中率 / 公平赔率 / 期望回报率 / 至少中 1 注的概率。
3. **历史回放** —— 可选最近 30 / 60 / 120 / 365 期或全部，逐期用「该期之前的数据」重算号码并核对命中，
   给出命中注数与 ROI、随机基线对照（无未来函数）；换范围会立刻重算，重摇随机号也会同步重算回放。
   筛选可切「全部 / 只看命中 / 只看部分命中」，再用「↑ 上一命中 / ↓ 下一命中」直接跳到那一期（自动加载更多 + 高亮行）。
4. **设置** —— 本金与赔率、版本与缓存维护（折叠块默认展开，随时可收起）。

已下线：自选号码、6 码试算、手动录入开奖、共识号、连空分布图、年份 / 搜索 / 自选方案等筛选控件。

## 数据从哪来（重要）

页面**不会自己去网上抓开奖**——「一键同步」读的是仓库里的静态文件 `data/draws.json`。
这个文件由 GitHub Actions 每天自动更新：

```
ci/sync-draws.yml                  源文件（可评审、可版本管理）
.github/workflows/sync-draws.yml   实际生效的位置 ← GitHub 只读这里
每日 21:45 起自动抓取 → 写回 draws.json + draws.js → 提交
```

## 同步为什么能「当天就到位」

开奖公布通常比停售晚 5~30 分钟，而 GitHub 的定时任务自己还会延迟甚至漏触发。
只靠「晚上跑三次、每次试一下」必然经常落空，落空就要等第二天。所以现在的策略是：

| 环节 | 做法 | 解决什么 |
| --- | --- | --- |
| **门控秒退** | 底库已有今天这期就立刻退出（不抓、不测、不提交） | 高频触发也不浪费额度 |
| **等待上游** | 抓到了但还没出今天这期 → 每 60 秒再抓，直到拿到 / 到 23:55 / 连续失败 10 次 | 不再靠「正好撞上发布时刻」 |
| **先提交再测试** | 脚本自己 `git commit` + `pull --rebase` + `push`（失败重试 3 次） | `npm test` 里任何一条与数据无关的断言飘红，都不会再把当天数据卡在门外 |
| **指数退避重试** | 抓取失败按 2 / 4 / 8 / 16 秒退避，最多 5 次；主源失败自动换备用源 | 上游是非标端口 + 坏证书，抖一下就丢一整天 |
| **原始文件兜底** | 页面发现本站 `data/draws.json` 落后时，会再读一次 `raw.githubusercontent.com` 上的同名文件 | Pages 每次提交要重新构建 30~90 秒，这期间页面看到的是旧数据 |

运行结果是三档，含义分得很清楚：

| 退出码 | 状态 | 含义 |
| --- | --- | --- |
| 0 | `ok` / `fresh` | 拿到今天这期，或本来就有 |
| 0 + `::warning::` | `not-published` | 等到 23:55 上游还没放榜（正常情况，不是故障） |
| 1 | `fetch-failed` | 站点不可达 / 解析不出记录（真故障，Actions 会标红） |

> ⚠ **历史 bug**：这个工作流以前放在仓库根目录的 `workflows/`，而 GitHub Actions **只**认 `.github/workflows/`，
> 所以它一次都没执行过，底库因此长期停在 2026-298。现在源文件放在 `ci/`，用一条命令安装到位：

```bash
npm run install:workflow     # 复制 ci/sync-draws.yml → .github/workflows/sync-draws.yml
git add .github/workflows/sync-draws.yml && git commit -m "ci: enable daily draw sync" && git push
```

> 为什么需要你手动提交一次：通过自动化令牌提交 workflow 文件会被 GitHub 拒绝
> （`refusing to allow a GitHub App to create or update workflow ... without workflows permission`）。
> 用你自己的账号提交就没有这个限制。也可以直接在网页上新建
> `.github/workflows/sync-draws.yml`，把 `ci/sync-draws.yml` 的内容粘进去。
> 装好后到 Actions 页面点一次 **Sync Daily Lottery Draws → Run workflow** 验证。
>
> **不装也能用**：`scripts/sync_latest.mjs` 自己会「门控 → 反复重抓 → 先提交」，
> 旧版的三次触发（21:45 / 22:15 / 23:00）同样能当天拿到数据。
> 装上 `ci/` 这一版只是更快（`21:00–23:55` 每 5 分钟探一次）也更省（其余时间秒退）。

为什么必须在服务端抓：上游 `https://2026kj.zkclhb.com:2025/am.html` 用的是**非标准端口 2025 + 不完整证书链**，
浏览器直连一定失败（证书 / CORS）；Node 脚本用 `rejectUnauthorized: false` 才抓得到。

所以「同步不到新数据」通常是这三种情况，页面会如实告诉你属于哪一种：

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 「仅检查」显示可追加 N 期 | **本机**落后，仓库里已经有新数据 | 点「一键同步」即可 |
| 本机新鲜度「落后 N 期」+ 可追加 0 期 | **仓库文件**本身没更新（Actions 还在等上游，或抓取真的坏了） | 看 Actions 里的 sync-draws：`not-published` 是上游还没发；`fetch-failed` 才是故障 |
| 本机新鲜度「已是最新」 | 真的没有新开奖 | 无需处理 |
| 读取失败 | 文件没部署 / 离线缓存异常 | 用「粘贴导入」兜底 |

## 运行

```bash
npm start          # 本地静态服务（默认 3000 端口）
npm test           # 单元测试 + 页面冒烟测试
npm run sync       # 手动从上游同步最新开奖到 data/draws.json（同时生成 draws.js）
npm run sync:wait  # 一直等到今天这期出现再写库并提交（CI 里就是这个模式）
npm run build:db   # 由 data/draws.json 重新生成 data/draws.js
npm run install:workflow   # 把 ci/sync-draws.yml 安装到 .github/workflows/（让自动同步生效）
```

页面冒烟测试用 jsdom 真跑一遍 `index.html + src/app.js`；没有装 jsdom 时会自动跳过（`npm i --no-save jsdom` 可启用）。
